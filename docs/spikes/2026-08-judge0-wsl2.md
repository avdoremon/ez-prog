## Gotchas

1. **Docker daemon is not running:** Docker Desktop is installed (v27.2.0), but the daemon is not active. Starting it requires machine owner authorization.

2. **No general-purpose WSL2 distro:** The system has only Docker Desktop's internal `docker-desktop` distro (stopped state). A general-purpose Linux distro (e.g., Ubuntu-22.04) must be installed and active to test Judge0.

3. **Privileged container requirement:** Judge0 requires `--privileged` containers to run `isolate`. This is a security-sensitive action on the machine owner's personal system and requires explicit authorization.

4. **Likely cgroup v1 dependency:** The brief notes that Judge0's `isolate` sandbox has a well-known dependency on cgroup v1. Windows 11 WSL2 often defaults to cgroup v2, which would fail at runtime. This was not verified due to environment constraints.

5. **Large image footprint:** Judge0 CE requires pulling ~2GB of images, which is a machine-level side effect outside this repository.

## Recommendation for Phase 1

**Prerequisites to execute the spike:**

1. Install a general-purpose Linux distro under WSL2:
   ```bash
   wsl --install Ubuntu-22.04
   ```

2. Ensure WSL2 is set as the default version for the new distro.

3. Start Docker Desktop and verify the daemon is responsive:
   ```bash
   docker info
   ```

4. Run the cgroup version check as a prerequisite:
   ```bash
   wsl -e stat -fc %T /sys/fs/cgroup
   ```
   - If the result is `cgroup2fs`, prepare for v2 incompatibility and consider fallbacks.

5. Execute the six-point checklist from `task-13-brief.md` Step 4 in order, stopping at the first failure.

6. Document findings in this note with actual pass/fail outcomes.

**If cgroup v2 blocks the spike:**

- **Fallback 1 (Recommended):** Run Judge0 on a dedicated Linux VM with cgroup v1 support (e.g., Ubuntu 22.04 LTS, verified to use cgroup v1 by default). This provides an isolated test environment and clearer failure diagnostics.

- **Fallback 2:** Evaluate an alternative code judge that does not require privileged containers (e.g., Piston API, Codechef Judge API, or a custom sandboxing solution with seccomp + user namespaces). Phase 1 should assess the trade-off between isolation strength and operational complexity.

**Timeline:** Phase 0 does not depend on this spike's outcome. Phase 1 planning can proceed with either outcome documented and prerequisites listed.
